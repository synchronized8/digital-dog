# 数字狗语音口型 Demo — MVP 规格

**创建日期：** 2026-06-23  
**状态：** 草稿  
**来源：** `docs/brainstorming/brainstorming-session-20260623-144420.md`  
**MVP 方案：** 方案 A：TTS 精准演示宠物舞台

**2026-06-24 平台纠偏：** 第一版展示设备更正为小米 Redmi Pad SE 11 英寸 MIUI / Android 平板。本文中的 iPadOS / iPad 表述均按 Redmi Pad SE / Android 原生平板方案解释。

## 目标

构建一个 Redmi Pad SE 11 英寸 MIUI / Android 原生展示 demo：用户在平板上启动后即可看到一只软萌数字狗，通过文字转语音、内置示例、上传音频或麦克风录音触发讲话表现；数字狗静音时闭口，讲话时以 7 类嘴型配合自然动作模拟发音，并通过调试台展示口型同步状态。

## 背景

当前项目只有头脑风暴产物，尚无 Android 平板实现。需求重点不是普通聊天页，而是验证“可爱好看”和“口型同步准确”两件事：数字狗应像一个虚拟宠物，被语音唤醒、讲话、结束并回到待机；同时 demo 要保留上传音频、麦克风录音、文字转语音和内置示例音频四种输入入口，为后续接入真实 AI 语音对话预留状态机。

## 用户与使用场景

**主要用户：** 需求方、设计评审者、Android 平板客户端开发者。

**核心场景：**

- 打开 iPad 展示端后，立刻理解这是一个可互动数字狗 demo。
- 输入一段文字，让数字狗用 TTS 讲话并展示口型变化。
- 一键播放内置示例，稳定观察完整效果。
- 上传音频或录制麦克风，验证非 TTS 输入也能驱动基础口型。
- 通过调试台查看当前嘴型、波形、时间轴、文本高亮和延迟校准。

## 范围

### 范围内

- Android 原生平板单屏 demo。
- 软萌虚拟宠物数字狗主舞台。
- 轻科技项圈状态反馈。
- 7 类嘴型视觉状态。
- 宠物状态机：`idle`、`listening`、`thinking`、`speaking`、`done`、`error`。
- 四种音频入口：文字转语音、内置示例、上传音频、麦克风录音。
- TTS 主路径的文本高亮和嘴型时间轴。
- 上传音频与麦克风录音的基础音频分析驱动。
- 调试台：当前嘴型、输入来源、波形、嘴型时间轴、延迟校准、解析质量。
- iPad 横屏优先、竖屏可用的展示布局。

### 范围外

- 真实 AI 对话接入。第一版只保留 mock 状态机。
- 完整 phoneme/viseme 语音识别。第一版使用近似映射与音频分析。
- 麦克风实时流式口型。第一版可先录制后回放分析。
- 多角色、多皮肤、多宠物选择。
- 用户账号、历史记录、云端存储。
- 生产级 TTS 服务选型和后端架构。

## 需求

1. **首屏可理解性**：首屏必须同时呈现数字狗、主输入入口、音频测试入口和调试反馈区域。
   - 当前：项目无 UI 实现。
   - 目标：用户启动 iPad 展示端后可在首屏看到宠物舞台、文字输入、示例音频、上传、麦克风和调试台。
   - 验收：在 iPad 横屏 `1194x834` 或 `1024x768` 逻辑尺寸下，首屏无需跳转即可看到核心体验入口；iPad 竖屏下调试台可折叠。

2. **数字狗待机状态**：未播放或录制音频时，数字狗必须保持闭口待机。
   - 当前：无状态机。
   - 目标：`idle` 状态下嘴型为 `closed`，身体有轻微呼吸，偶尔眨眼。
   - 验收：页面加载后、讲话结束 1 秒内、错误反馈结束后，嘴型均回到 `closed`。

3. **讲话行为循环**：TTS 和示例音频触发后，数字狗必须完成准备、讲话、结束、待机的完整循环。
   - 当前：无交互流程。
   - 目标：触发讲话后依次进入 `listening` 或 `thinking`、`speaking`、`done`、`idle`。
   - 验收：点击“让狗狗说话”后，状态指示和宠物动作按顺序变化，音频结束后自动回到 `idle`。

4. **7 类嘴型集合**：第一版必须提供 7 类可区分的嘴型。
   - 当前：无数字狗形象。
   - 目标：支持 `closed`、`small`、`wide`、`round`、`smile`、`teeth`、`pant`。
   - 验收：调试台可手动或通过播放流程触发每一种嘴型，视觉差异可被观察到。

5. **文字转语音主入口**：用户必须能输入文本并触发数字狗讲话。
   - 当前：无输入控件。
   - 目标：文本输入框和主按钮触发 TTS 或模拟 TTS 播放流程。
   - 验收：输入非空文本后点击主按钮，数字狗进入讲话循环，文本高亮和嘴型时间轴同步推进。

6. **内置示例音频**：demo 必须提供不依赖用户输入的稳定演示入口。
   - 当前：无示例。
   - 目标：“播放示例”触发一段内置音频或预设时间轴。
   - 验收：用户不输入文本、不授权麦克风，也能一键看到完整讲话和口型效果。

7. **上传音频入口**：用户必须能上传本地音频进行基础口型驱动。
   - 当前：无上传入口。
   - 目标：支持选择音频文件，播放后按音量和频谱驱动基础嘴型。
   - 验收：上传合法音频后可播放；调试台显示输入来源为上传音频、解析质量和当前嘴型。

8. **麦克风录音入口**：用户必须能通过麦克风录制短音频进行基础口型驱动。
   - 当前：无麦克风入口。
   - 目标：支持开始录音、停止录音、回放录音并驱动基础嘴型。
   - 验收：授权成功时可录制并回放；授权失败时进入 `error` 状态并显示可恢复错误。

9. **调试台可观察性**：demo 必须能观察口型同步是否工作。
   - 当前：无调试反馈。
   - 目标：调试台显示当前嘴型、输入来源、波形、嘴型时间轴、TTS 文本高亮和延迟校准。
   - 验收：播放中当前嘴型标签实时变化，时间轴进度随播放推进，延迟校准值可调整。

10. **状态错误处理**：空输入、麦克风拒绝、音频解析失败必须有可见反馈。
    - 当前：无错误处理。
    - 目标：错误进入 `error` 状态，狗狗歪头或疑惑，项圈提示色变化，界面显示问题和恢复路径。
    - 验收：空文本点击主按钮不触发讲话；麦克风拒绝后显示错误并可继续使用 TTS 或示例音频。

11. **AI 对话预留**：第一版必须保留未来 AI 对话状态，不接真实 AI。
    - 当前：无状态接口。
    - 目标：状态机包含 `listening`、`thinking`、`speaking`、`done`、`error`，可由 mock 事件触发。
    - 验收：开发测试入口或内部事件可触发每个状态；真实 AI 接入不需要重做宠物状态命名。

12. **iPad 展示布局**：iPad 横屏和竖屏都必须可用。
    - 当前：无布局。
    - 目标：iPad 横屏使用宠物舞台 + 调试台双栏；iPad 竖屏宠物舞台优先，调试台折叠。
    - 验收：在 `1194x834`、`1024x768`、`834x1194` 三种 iPad 逻辑尺寸下，核心控件不重叠，文字不溢出按钮或面板。

## 宠物状态机

| 状态 | 触发 | 视觉表现 | 下一状态 |
| --- | --- | --- | --- |
| `idle` | 页面加载、讲话结束、错误恢复 | 闭口、呼吸、偶尔眨眼、项圈低亮 | `listening` / `thinking` / `speaking` / `error` |
| `listening` | 麦克风录音、准备播放、mock 对话聆听 | 耳朵竖起、看向用户、项圈蓝光 | `thinking` / `speaking` / `error` |
| `thinking` | TTS 准备、mock AI 思考 | 闭口、轻微歪头、项圈呼吸光 | `speaking` / `error` |
| `speaking` | 音频或 TTS 播放中 | 7 类嘴型切换、头部轻动、身体前倾 | `done` / `error` |
| `done` | 播放结束 | 闭口、眨眼、尾巴轻摇 | `idle` |
| `error` | 无输入、权限失败、解析失败 | 疑惑表情、歪头、项圈黄光 | `idle` |

## 口型集合

| 嘴型 | 用途 | 视觉要求 |
| --- | --- | --- |
| `closed` | 静音、停顿、闭唇音 | 嘴线闭合，不能有开口 |
| `small` | 普通短音、轻声 | 小幅张口 |
| `wide` | 重音、大元音 | 纵向明显张口 |
| `round` | o/u 类感觉 | 圆形或椭圆嘴 |
| `smile` | e/i 类感觉 | 横向咧嘴，略带微笑 |
| `teeth` | f/v/s/th 类摩擦音感觉 | 轻微露齿或咬合 |
| `pant` | 宠物开心喘气或非语言反馈 | 更可爱，不能替代正常发音嘴型 |

## 输入与口型驱动策略

| 输入来源 | 优先级 | 驱动策略 | 验收重点 |
| --- | --- | --- | --- |
| 文字转语音 | 主入口 | 文本估算 viseme + 时间轴 + 音量节奏修正 | 口型、文本高亮、状态循环稳定 |
| 内置示例音频 | 次入口 | 预设时间轴或稳定音频分析 | 一键可演示，不依赖权限 |
| 上传音频 | 实验入口 | 音量包络 + 频谱粗分 | 可播放，可驱动基础嘴型，显示解析质量 |
| 麦克风录音 | 实验入口 | 录制后回放分析 | 授权成功可用，拒绝有错误反馈 |

## 约束

- 第一版必须是 iPadOS 原生展示端，不是网页 UI。
- 首屏必须是实际 demo，不做营销落地页。
- 主体验必须优先体现软萌宠物，调试台不能压过数字狗。
- UI 不使用大面积单一色相；软萌感通过形体、动效和局部色彩表达。
- 调试信息必须可见，但不能覆盖数字狗嘴型。
- 静音段必须回到 `closed`。
- 辅助动作必须克制，不能干扰嘴型观察。
- 麦克风权限失败不能阻塞 TTS 和内置示例。

## 验收清单

- [ ] 首屏展示数字狗、TTS 主入口、示例音频、上传、麦克风和调试台。
- [ ] 页面加载后数字狗处于 `idle`，嘴型为 `closed`。
- [ ] TTS 输入非空文本后触发完整讲话循环。
- [ ] TTS 播放中至少展示 4 种以上嘴型，且系统支持全部 7 类嘴型。
- [ ] 文本高亮、嘴型时间轴和当前嘴型标签随播放推进。
- [ ] 示例音频无需文本和麦克风权限即可稳定演示。
- [ ] 上传音频可播放并驱动基础嘴型。
- [ ] 麦克风录音可录制、停止、回放并驱动基础嘴型。
- [ ] 空文本、麦克风拒绝、音频解析失败进入 `error` 状态。
- [ ] 延迟校准控件可调整并影响嘴型时间轴偏移。
- [ ] iPad 横屏和竖屏核心控件无重叠、无文字溢出。
- [ ] 状态机保留未来 AI 对话所需状态。

## 风险与处理

| 风险 | 处理方式 |
| --- | --- |
| TTS 时间不可精确控制 | 第一版允许使用 `AVSpeechSynthesizer`、预设 TTS 或模拟 TTS 时间轴；用调试台显示偏移 |
| 上传音频口型不准 | 标记为实验入口，并显示解析质量 |
| 麦克风权限失败 | 明确错误反馈，不影响 TTS 和示例音频 |
| 嘴型乱跳 | 添加最短保持时间和平滑过渡 |
| 动作过多干扰口型 | 讲话时限制头、耳、尾动作幅度 |
| UI 太工具化 | 宠物舞台占主视觉，调试台辅助 |
| UI 太玩具化 | 保留波形、时间轴、延迟校准等工程信息 |

## 推荐实施顺序

1. 静态首屏布局和数字狗基础形象。
2. 宠物状态机。
3. 7 类嘴型视觉状态和手动测试。
4. TTS 主路径与嘴型时间轴。
5. 调试台：当前嘴型、波形、时间轴、文本高亮、延迟校准。
6. 内置示例音频。
7. 上传音频与麦克风录音。
8. 可爱反馈、错误状态和 iPad 横竖屏布局打磨。
