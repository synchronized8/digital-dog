# 数字狗可爱讲话动画 Demo - MVP 规格

**创建日期：** 2026-06-23
**更新日期：** 2026-06-25
**状态：** 当前执行版
**来源：** `docs/brainstorming/brainstorming-session-20260623-144420.md`、`docs/planning-artifacts/epics.md`
**MVP 方案：** 简单小狗讲话动画 UI

## 决策摘要

当前 MVP 已从“精确口型同步 Demo”简化为“可爱小狗讲话动画 UI”。本规格是当前 Sprint 的执行口径。

当前版本只要求用户能通过文本或示例触发小狗讲话动画：讲话时张口或轻微开合，不讲话时闭口，并用少量俏皮动作表达生命感。当前 MVP 不要求口型与文本、音素、声音节奏或时间轴精确同步。

## 目标

构建一个 Redmi Pad SE 11 英寸 MIUI / Android 原生展示 demo。用户打开 App 后，首屏看到一只可爱小狗、文本输入、`让狗狗说话` 和 `播放示例`。用户输入一句话或点击示例后，小狗完成准备、讲话、完成、回待机的循环。

成功体验是：评审者不用理解调试信息，也能马上判断“小狗可爱，并且像是在回应我讲话”。

## 当前范围内

- Android 原生平板单屏 demo，Kotlin + Jetpack Compose。
- Redmi Pad SE 横屏优先、竖屏可用布局。
- 软萌小狗宠物舞台。
- 文本主入口：输入非空文本后触发讲话流程。
- 示例入口：不输入文本也能一键触发讲话流程。
- 宠物状态：`idle`、`thinking` 或准备态、`speaking`、`done`、`error`；可保留 `listening` 作为未来 AI 预留状态。
- 最小嘴巴规则：`speaking` 时张口或轻微开合，其他状态闭口。
- 俏皮但克制的准备、讲话中和完成反馈动作。
- 轻量状态摘要：当前状态、输入来源、嘴巴状态。
- 空文本、忙碌重复触发、错误恢复、减少动态和基础 TalkBack 语义。

## 当前范围外

- 精确口型同步。
- 7 类嘴型作为 MVP 验收目标。
- `LipSyncTimeline` 作为强制播放路径。
- TTS 文本高亮、波形、嘴型时间轴可视化、延迟校准。
- 上传音频、麦克风录音、音频解码分析。
- 生产级 TTS、真实 AI 对话、实时流式音频分析。
- 账号、历史记录、云端存储、多宠物、多皮肤。

历史完成过的 `LipSyncTimeline`、7 类嘴型或调试能力已从当前 production 路径移除或收敛为简单模型；不得作为当前 MVP 的新增验收入口继续扩展。

## 用户与场景

**主要用户：** 需求方、设计评审者、Android 平板客户端开发者。

**核心场景：**

- 评审者打开 Redmi Pad SE，立刻看到小狗舞台和输入入口。
- 用户输入一句话，点击 `让狗狗说话`，看到小狗准备、讲话、完成并回到待机。
- 用户点击 `播放示例`，不输入文本也能稳定看到同样的讲话动画。
- 用户提交空文本时看到可恢复错误，并能继续输入或播放示例。

## 功能需求

### FR-1：首屏可理解

首屏必须展示小狗舞台、文本输入、主 CTA、示例入口和轻量状态摘要。

验收：

- Redmi Pad SE 横屏等价视口下，小狗舞台是视觉中心。
- 竖屏下核心控件不重叠，按钮和标签不溢出。
- 首屏不是营销介绍页，也不展示复杂调试图表。

### FR-2：待机闭口

小狗在页面加载、未讲话、错误恢复和讲话完成后必须闭口。

验收：

- 初始状态为 `idle`，嘴巴为 `closed`。
- `thinking`、`done`、`error` 状态下嘴巴为 `closed`。
- 讲话流程结束后自动回到 `idle` 和 `closed`。

### FR-3：文本主入口

用户可以输入非空文本并点击 `让狗狗说话` 触发讲话动画。

验收：

- 非空文本提交后创建一次讲话流程。
- 准备阶段嘴巴保持 `closed`。
- 进入 `speaking` 后嘴巴张口或轻微开合。
- 播放中主 CTA 禁用或切换为停止状态，不创建第二个冲突流程。

### FR-4：示例入口

用户可以点击 `播放示例` 稳定触发讲话动画。

验收：

- 不输入文本也可以播放示例。
- 示例入口不依赖麦克风权限。
- 示例流程和文本流程共享同一套宠物状态、嘴巴规则和完成反馈。

### FR-5：讲话行为循环

讲话流程必须形成准备、讲话、完成、回待机的完整循环。

验收：

- 准备阶段可出现耳朵竖起、看向用户或歪头动作，嘴巴仍闭合。
- 讲话阶段嘴巴张口或轻微开合，不要求对齐文本、音素、声音节奏或时间轴。
- 完成阶段出现一次短反馈，例如眨眼、摇尾或开心表情。
- 完成反馈后回到 `idle`。

### FR-6：错误恢复

空文本和播放中重复触发必须有可恢复反馈。

验收：

- 空文本点击主按钮不触发讲话。
- 输入区显示 `先输入一句话`。
- 小狗进入 `error`，嘴巴为 `closed`。
- 用户可继续编辑文本或播放示例。

### FR-7：轻量状态摘要

界面必须表达当前状态、输入来源和嘴巴状态，但不得变成调试台。

验收：

- 状态摘要最多显示当前状态、输入来源、嘴巴状态。
- 状态颜色必须配合文字或标签表达。
- 默认 UI 不展示波形、时间轴、文本高亮或延迟校准。

### FR-8：可访问性与减少动态

核心操作必须支持触控、键盘焦点和 TalkBack；减少动态时仍能看出小狗在讲话。

验收：

- 主按钮、文本输入、示例入口和错误反馈可被 TalkBack 理解。
- 宠物图形可设为装饰，但当前状态和嘴巴状态必须有文字语义。
- 减少动态时降低耳朵、头部、身体和尾巴动作，但保留讲话开口。
- 触控目标不小于 48dp。

## 约束

- 第一版必须是 Android 原生平板展示端，不是网页 UI。
- 首屏必须是实际 demo，不做营销落地页。
- 主体验必须是软萌宠物，状态摘要不能压过小狗舞台。
- UI 不使用大面积单一色相、装饰性渐变球或过度工具化控制台视觉。
- 播放中组件尺寸稳定，按钮、标签和文本不得造成布局跳动。
- 当前 MVP 不请求麦克风权限，不打开文件选择器。

## 验收清单

- [ ] 首屏展示小狗舞台、文本输入、`让狗狗说话` 和 `播放示例`。
- [ ] 页面加载后小狗处于 `idle`，嘴巴为 `closed`。
- [ ] 非空文本触发准备、讲话、完成、回待机。
- [ ] 示例入口无需文本即可触发同样流程。
- [ ] `speaking` 时嘴巴张口或轻微开合。
- [ ] 非 `speaking` 状态嘴巴闭合。
- [ ] 空文本进入可恢复 `error`，显示 `先输入一句话`。
- [ ] 播放中不会创建第二个冲突讲话流程。
- [ ] 默认 UI 不显示波形、时间轴、文本高亮、延迟校准、上传或麦克风。
- [ ] Redmi Pad SE 横屏和竖屏核心控件无重叠、无文字溢出。
- [ ] TalkBack 和减少动态策略可用。

## 推荐实施顺序

1. 固定默认 UI：小狗舞台、文本输入、主 CTA、示例入口、轻量状态摘要。
2. 打通状态流：`idle -> thinking/preparing -> speaking -> done -> idle`，错误可恢复。
3. 实现最小嘴巴规则：`speaking` 张口或开合，其他状态闭口。
4. 加入俏皮动作和完成反馈。
5. 补齐空文本、忙碌重复触发、减少动态和 TalkBack 测试。
6. 增加边界测试，确保默认 UI 不出现 deferred 功能。
