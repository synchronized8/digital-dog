# Story 2.5：简化演示入口与 UI 清理

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 使用者,
I want 首屏只保留小狗舞台、文本输入、让狗狗说话和示例入口,
so that 我能直接试小狗讲话动画，不被调试项干扰。

## Acceptance Criteria

1. Given App 默认启动, When 首屏渲染, Then 可见宠物舞台、TTS 输入、主 CTA 和示例入口。
2. Given 用户未展开任何开发入口, When 检查默认 UI, Then 不展示波形、嘴型时间轴、文本高亮或延迟校准。
3. Given 当前 MVP 范围, When 检查默认 UI, Then 上传音频和麦克风入口被移除，或隐藏到非默认开发入口。
4. Given 状态摘要渲染, When 小狗状态变化, Then 摘要最多显示当前状态、嘴巴状态和输入来源等轻量信息。
5. Given 横屏和竖屏视口, When 核心控件渲染, Then 按钮和标签不重叠、不溢出。
6. Given TalkBack 读取默认页面, When 焦点经过主流程控件, Then 名称和值清晰可读。
7. Scope boundary: 本 Story 不新增上传、麦克风、波形、嘴型时间轴、文本高亮、延迟校准、完整调试台、真实音频、真实 TTS、真实 AI、网络、数据库或新三方依赖。
8. Validation: `:app:testDebugUnitTest`, `:app:assembleDebug`, `:app:compileDebugAndroidTestKotlin`, `:app:lintDebug` 必须通过；如 `adb devices` 有可用设备, 运行并记录 `:app:connectedDebugAndroidTest`。

## Dev Notes

### 当前 Story 目标

Story 2.5 是 UI 收敛和护栏补强，不是新功能扩展。当前代码已经完成大量 MVP 范围重置：旧的 lipsync/audio/debug 路径已从当前 production tree 中删除，默认 UI 已接近目标。实施时要以“确认并补强默认体验”为主，避免为了清理 UI 而重写状态流或恢复旧调试能力。

成功标准：

- 默认页面看起来是可直接使用的小狗讲话 Demo，而不是调试工具。
- 文本输入和示例入口清晰可用。
- 状态摘要轻，不抢小狗舞台的注意力。
- 横竖屏、触控目标和 TalkBack 覆盖比当前更硬。
- 默认 UI 和代码边界继续阻止 deferred 能力回流。

  - 容器语义已有 `SpeechInputDescription`，quick actions 语义已有 `QuickActionsDescription`；2.5 应在 Android 测试中直接断言这些语义。

  - 是默认 UI 文案、语义和 test tag 的稳定来源；新增/调整测试应引用 contract，不散落硬编码字符串，除非是在范围边界测试中明确断言 forbidden UI 文案不存在。
- `StoryTwoFourScopeBoundaryTest.kt`

  - 2.5 可复用其项目根发现、文件扫描、dependency allowlist 和 `stripBoundaryAssertionLiterals` 思路，但 forbidden tokens 应聚焦 UI 清理边界。

### Architecture Compliance

- 不新增第二套页面结构、状态 store、router、debug drawer 或 feature flag 系统。
- 不把上传/麦克风/波形/时间轴作为“隐藏但默认构建”的 UI 加回当前 app。
- 不为了测试范围边界而在 production 中新增无意义 wrapper；优先通过现有 contract、semantics 和 tests 验证。
- `DigitalDogApp` 仍是实际可用体验的第一屏；不得变成说明页、landing page 或调试选择页。
- 状态摘要只能辅助理解，不得替代宠物舞台成为主视觉。
