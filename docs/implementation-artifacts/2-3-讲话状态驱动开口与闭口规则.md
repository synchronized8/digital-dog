# Story 2.3：讲话状态驱动开口与闭口规则

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 评审者,
I want 点击“让狗狗说话”后看到小狗张口讲话，不讲话时闭口,
so that 我能快速判断这是一只会回应的可爱数字狗，而不是复杂同步工具.

## Acceptance Criteria

1. Given App 处于 `idle`, When 用户提交非空文本, Then 小狗进入准备或 `speaking` 流程, And 准备阶段嘴巴保持 `closed`.
2. Given 小狗进入 `speaking`, When 讲话动画运行, Then 嘴巴进入 `talking/open` 状态或轻微开合循环, And 不要求与文本、音素、声音节奏或 `LipSyncTimeline` 对齐.
3. Given 小狗未处于 `speaking`, When 用户观察待机、思考、错误或完成状态, Then 嘴巴必须为 `closed`.
4. Given 讲话动画结束, When 完成反馈结束, Then 小狗回到 `idle`, And 嘴巴为 `closed`.
5. Given 当前已有讲话 session 进行中, When 用户再次触发主 CTA, Then 不创建第二个冲突 session, And 当前讲话动画不被中途替换.
6. Scope boundary: 本 Story 不新增波形、文本高亮、延迟校准、上传音频、麦克风录音、音频分析、真实 Android `TextToSpeech` 发声、播放时钟、时间轴 UI、网络、数据库、真实 AI 或新三方依赖.
7. Validation: `:app:testDebugUnitTest`, `:app:assembleDebug`, `:app:compileDebugAndroidTestKotlin`, `:app:lintDebug` 必须通过；如当前环境有可用模拟器或设备, 运行并记录 `:app:connectedDebugAndroidTest`.

## Dev Notes

### 当前 Story 目标

2026-06-25 correct-course 已将当前 MVP 从“精确口型同步 Demo”重置为“简单小狗讲话动画 UI”。本 Story 是新范围下的第一条实施 Story: 用 speaking 状态直接驱动小狗张口/闭口, 不再继续扩展时间轴、文本高亮、波形或延迟校准。

本 Story 的关键验收不是“口型是否同步”, 而是:

- 非讲话状态闭口.
- 讲话状态明显张口或轻微开合.
- 讲话流程能从提交进入, 并能结束回到闭口待机.
- UI 和语义都能表达当前嘴巴状态.

### Implementation Guidance

- 当前 production 只保留 `MouthShape.Closed` 和 `MouthShape.Open`, 表达闭口和讲话张口.
- 如果需要表达“讲话嘴”给语义或测试, 可在 `AppContentContract` 增加用户可读文案, 例如 `嘴巴状态：张口讲话`.
- Story 2.2 文件保留为历史记录；旧 timeline production 代码已删除, 主路径已切到 speaking animation.
- 不要为模拟讲话引入真实计时器导致测试不稳定. 如需时间推进, 优先提供可测试的 reducer event, 例如 `startSpeaking()` / `completeSpeaking()`.
- 保持 reduced-motion 规则: 减少动态只降低装饰动作, 不能让 speaking 嘴巴状态不可见.
