# Epic 2 Retrospective：简单讲话动画与俏皮反馈

Date: 2026-06-26
Status: complete

## Summary

Epic 2 completed the current MVP speech loop for the Digital Dog Android demo.

Delivered stories:

- 2.1 TTS 主入口提交与空文本处理
- 2.2 TTS 文本到嘴型时间轴生成
- 2.3 讲话状态驱动开口与闭口规则
- 2.4 俏皮动作编排与讲话结束反馈
- 2.5 简化演示入口与 UI 清理
- 2.6 简化讲话动画测试覆盖

Current MVP result:

- Text input and sample entry both trigger the same preparation, speaking, done, and idle loop.
- Speaking uses the current MVP rule: speaking means open or talking mouth, non-speaking means closed mouth.
- Empty text and busy repeated submissions are recoverable and covered by tests.
- Default UI no longer exposes deferred waveform, timeline, text highlight, delay calibration, upload, microphone, or full debug console capabilities.
- Epic 3 and Epic 4 remain deferred future scope, not current implementation work.

## What Worked

- The scope reset was effective. Moving from precision lip-sync to a simple cute speech animation kept the MVP testable and shippable.
- Story-by-story code review caught concrete issues before closure, including state transition guards, delayed auto-advance, accessibility semantics, and boundary coverage.
- The final test matrix now covers reducer lifecycle, UI semantics, reduced motion, layout stability, and deferred-feature guards.
- The implementation kept the default experience focused on the pet stage, text input, sample entry, and lightweight status summary.

## Challenges

- Earlier Epic 2 work still carried historical precision-sync assumptions. Several review findings came from old timeline/debug/audio concepts bleeding into the current MVP.
- The worktree accumulated multiple uncommitted story changes, which made diff-based review noisier and required careful scoping during Story 2.6 review.
- Some implementation records had stale generated text and needed cleanup during review closure.
- Connected Android instrumentation could not be run because no device was attached.

## Key Learnings

- Scope boundaries need executable tests when a project intentionally removes or defers previously planned capabilities.
- Deferred work should remain documented, but production paths and default UI must not continue to depend on deferred concepts.
- For this app, `PetState`, `MouthShape`, `InputSource`, and `SpeechAnimationState` are the practical current contract. Older session/status fields should not be treated as active lifecycle truth unless they are cleaned up.
- Code review is most useful when it separates true current-story defects from historical or diff-scope noise.
