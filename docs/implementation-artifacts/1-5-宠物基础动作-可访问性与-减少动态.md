# Story 1.5：宠物基础动作、可访问性与减少动态

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 评审者,
I want 数字狗在待机、准备、讲话、完成和错误时有自然克制的动作反馈,
so that 它看起来像软萌宠物，而不是静态图或过度表演的玩具.

## Acceptance Criteria

1. Given 数字狗处于 idle/待机状态, When 用户没有输入, Then 嘴型保持闭口, 身体有轻微呼吸感或偶发眨眼, 且不造成布局跳动.
2. Given mock 状态机进入准备、讲话、完成或错误状态, When 宠物舞台刷新, Then 耳朵、眼睛、头部、身体、尾巴或项圈中至少一个元素给出对应反馈, 且 speaking 的辅助动作不得遮挡嘴型.
3. Given Android 系统动画比例关闭/降低, 或应用内进入减少动态模式, When 宠物舞台显示任意状态, Then 装饰性的耳朵、头部、身体、尾巴动作应降低或关闭, 但必要的嘴型状态仍可观察.
4. Given TalkBack 焦点到达宠物状态摘要, When 朗读当前舞台, Then 用户能听到当前宠物状态与当前嘴型, 宠物图形本身可以作为装饰图形处理, 不重复朗读复杂图形细节.
5. Scope boundary: 本 Story 不实现 TTS、音频播放、音频上传、麦克风、LipSyncTimeline、波形、文本高亮、延迟校准、真实 AI、网络、数据库、权限申请或新三方动画依赖.
6. Validation: `:app:testDebugUnitTest`, `:app:assembleDebug`, `:app:compileDebugAndroidTestKotlin`, `:app:lintDebug` 必须通过；如当前环境有可用模拟器或设备, 运行并记录 `:app:connectedDebugAndroidTest`.

## Dev Notes

### 当前 Story 目标

本 Story 是 Epic 1 的最后一个功能 Story, 目标是在现有数字狗舞台和 7 类嘴型基础上加入克制、可测试、可降级的基础动作反馈。实现应让 idle、listening/thinking、speaking、done、error 在视觉和可访问性摘要上都可区分, 但不得进入 Epic 2 的 TTS/嘴型时间轴范围。

必须优先继承 Story 1.4 的实现结果: 当前嘴型可以由手动入口控制, 舞台语义已经包含输入源, 非闭口手动嘴型不应被描述为闭口待机。本 Story 的动作层只能消费状态、嘴型和减少动态策略, 不应反向修改状态机或嘴型状态。

### 技术要求

- 使用 Kotlin + Jetpack Compose；不要引入新三方动画库.
- 动作应通过稳定容器内的 alpha、rotation、translation、scale 或 offset 等绘制/变换层完成, 不改变外层 layout 约束.
- 动作必须克制, 目标是软萌和状态可理解, 不是夸张表演.
- `speaking` 中嘴型是最高优先级视觉元素；头、身体、耳朵、尾巴动作不能遮挡嘴型.
- reduced-motion 应是显式、可测试的策略, 不依赖测试修改 Android 全局设置.
- 渲染层只消费 `PetUiState`、mouth 和 motion policy, 不创建新状态机, 不自行推进业务状态.
- 保持 Story 1.4 的所有嘴型 id、label、manual control、input source 和 stage semantics 行为.

### 架构合规要求

- 包边界应贴合现有结构:
  - 动作绘制或 profile: `dogrenderer` 或 `petstage`.
  - 可访问性/减少动态策略: `accessibility`.
  - 状态展示映射: `petstate`.
  - 页面参数注入: `DigitalDogApp.kt`.
- 不新增网络、数据库、音频、TTS、权限、后台 service 或 Android manifest 权限.
- 不把 Android framework 读取逻辑直接塞进纯 JVM 可测模型；若需要读取系统动画比例, 用小 adapter 隔离.
- 不让 debug 面板成为状态来源；debug/summary 仍只反映当前 `PetUiState`.

### UI 与动作契约

- idle: 嘴型闭口, 轻微呼吸或偶发眨眼, 不移动舞台外框, 不造成布局跳动.
- listening: 耳朵、眼睛或项圈体现正在接收输入, 但仍保持舞台稳定.
- thinking: 闭口思考, 可轻微歪头或项圈变化, 幅度低.
- speaking: 当前嘴型必须清晰可见；辅助头身动作低幅且不覆盖嘴.
- done: 可用眨眼、尾巴或项圈表达完成, 但不夸张跳动.
- error: 可用困惑眼神、轻微歪头和黄色项圈表达异常, 同时保留文本状态.
- reduced-motion: 保留状态和嘴型可观察性, 降低或关闭装饰动作；必要状态信息通过文本/语义补足.

### Motion Timing and Test Stability

- 参考 UX/UI-SPEC 的时序范围: 嘴型 80-140ms, 眨眼 120-180ms, 耳朵 180-260ms, 头部 180-320ms, 呼吸 2400-3600ms, 尾巴 500-900ms, error tilt 300-450ms.
- 动作幅度应低且可读, 推荐通过小角度 rotation、小 dp translation 或轻微 alpha/scale 表达, 不应出现跳跃、弹跳或舞台整体位移.
- 如果使用 `rememberInfiniteTransition` 或循环动画, 必须能通过 reduced/static policy 在测试中关闭或冻结, 避免 Android Compose test 因持续动画产生不稳定等待.
- reduced-motion 和测试静态路径不能改变状态、嘴型或语义摘要, 只能改变装饰动画的播放方式.

### 可访问性要求

- TalkBack 聚焦宠物舞台或状态摘要时, 应听到当前宠物状态、当前嘴型、输入源和动作/减少动态摘要.
- 宠物图形中的耳朵、眼睛、身体等装饰形状不应逐个成为复杂可聚焦节点.
- 不应通过每帧动画反复触发公告或语义变更噪音.
- 状态不能只用颜色表达；项圈颜色仍可作为辅助, 但必须有文本/语义描述.
- 控件 touch target 和现有 test tag 不应因动作层重构而退化.

- Jetpack Compose 官方动画指南建议使用 Compose 内建 animation APIs 和修饰符驱动 UI 动画；本 Story 应优先使用现有 Compose 能力, 不引入新动画库.
- `androidx.compose.ui.MotionDurationScale` 的 `scaleFactor == 0f` 表示动画应立即完成, 可作为 Compose reduced-motion 行为的重要参考.
- Android `ValueAnimator.getDurationScale()` 可读取系统动画时长比例, 但实现中应隔离平台读取并保持测试可注入, 不直接耦合到 UI 纯逻辑.
- Compose semantics 官方文档支持通过 semantics/content description 暴露控件状态；本 Story 的 TalkBack 目标应放在稳定摘要, 不放在每个图形子部件.
