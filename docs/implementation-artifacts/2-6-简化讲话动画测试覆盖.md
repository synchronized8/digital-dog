## Story

As a 开发者,
I want 用测试覆盖讲话状态、开闭口规则和范围边界,
so that 后续 UI 调整不会破坏最小讲话体验。

## Acceptance Criteria

1. Given 运行逻辑测试, When 非空文本提交, Then 创建一次讲话流程并能进入 `speaking`。
2. Given 运行逻辑测试, When 空文本提交, Then 状态进入可恢复 `error` 且嘴巴为 `closed`。
3. Given 运行逻辑测试, When 忙碌状态重复提交, Then 不创建第二个讲话 session。
4. Given 运行开闭口规则测试, When 状态为 `speaking`, Then 嘴巴为 `open/talking`。
5. Given 运行开闭口规则测试, When 状态不是 `speaking`, Then 嘴巴为 `closed`。
6. Given 运行 UI 或语义测试, When 点击主 CTA 或示例入口, Then 舞台进入讲话/张口状态。
7. Given 运行边界测试或手动验收, When 检查默认 UI, Then 不新增波形、时间轴、文本高亮、延迟校准、上传、麦克风或新音频分析依赖。
8. Scope boundary: 本 Story 以测试补强为主；除非新增测试暴露真实缺陷，不改生产逻辑；不新增第三方依赖、网络、数据库、真实 TTS、真实音频、上传、麦克风、波形、时间轴、文本高亮、延迟校准或完整调试台。
9. Validation: `:app:testDebugUnitTest`, `:app:assembleDebug`, `:app:compileDebugAndroidTestKotlin`, `:app:lintDebug` 必须通过；如 `adb devices` 有可用设备, 运行并记录 `:app:connectedDebugAndroidTest`。

## Dev Notes

### 当前 Story 目标

Story 2.6 是 Epic 2 的测试护栏 Story。目标不是实现新 UI，也不是恢复旧的精确口型同步能力，而是把当前 MVP 的最小讲话体验用测试固定住：

- 文本和示例都能触发同一套准备、讲话、完成、回待机流程。
- `speaking` 是当前唯一的讲话嘴业务状态；非 `speaking` 默认闭口。
- 空文本和忙碌重复触发可恢复且不会产生冲突 session。
- 默认 UI 和代码边界继续阻止 deferred 的 lipsync/debug/audio 能力回流。

实现时先映射现有测试覆盖，再补缺口。不要为了“新增测试数量”制造重复或脆弱测试。

### Existing Code Notes

- `DigitalDog/app/src/main/java/com/digitaldog/demo/state/TtsSubmitReducer.kt`
  - `submitText` 会 trim 并压缩空白；非空文本进入 `PetState.Thinking`、`MouthShape.Closed`、`InputSource.Tts`、`SpeechAnimationState.Preparing`，并创建 `text-{nextSpeechSessionIndex}` session。
  - `playSample` 使用固定文案 `汪，今天也要开心呀`，进入同样准备状态，输入来源为 `InputSource.Sample`，不改 `ttsInputText`。
  - `startSpeech` 在 `current.isSpeechSessionBusy` 为 true 时直接返回 current，这是 busy guard 的核心。
  - 空文本提交返回 `PetState.Error`、`MouthShape.Closed`、`InputSource.Tts`、`inputError = EmptyTtsInputError`，且 active session 为 null。
  - `startSpeaking` 只在 active session 存在且 `petState == Thinking` 时进入 `Speaking` + `MouthShape.Open`。
  - `completeSpeaking` 只在 `Speaking` 且 active session 存在时进入 `Done` + `MouthShape.Closed`，并清 active session。
  - `returnToIdleAfterCompletion` 只在 `Done` 时回 `Idle` + `MouthShape.Closed` + `InputSource.None`。
  - 已知 review carryover: `nextSpeechSessionIndex + 1` 在 `Int.MAX_VALUE` 后可能溢出。2.6 可用测试暴露并做最小修复。
- `DigitalDog/app/src/main/java/com/digitaldog/demo/state/PetStateReducer.kt`
  - `EnterSpeaking` 映射 `MouthShape.Open` 和 `SpeechAnimationState.Speaking`。
  - 其他 event 映射 `MouthShape.Closed`，其中 `EnterThinking` 为 `Preparing`、`EnterDone` 为 `Done`、`EnterError` 为 `DogActionCue.HeadTilt`。
  - 该 reducer 是历史/辅助 reducer；主 CTA 和示例路径当前主要走 `TtsSubmitReducer`。
- `DigitalDog/app/src/main/java/com/digitaldog/demo/app/DigitalDogApp.kt`
  - `DigitalDogApp` 持有 `currentUiState`，从 `TtsSubmitReducer` 接收文本、提交和示例事件。
  - `LaunchedEffect` 基于 `petState`, active session id 和 `speechAnimationState` 自动推进：`Thinking -> Speaking -> Done -> Idle`。
  - `safeDelayMillis()` 使用 `estimatedDurationMs.coerceAtLeast(0)`，负 duration 不应崩溃。
  - `TopStatusBar` contentDescription 由 `AppContentContract.statusBarDescription(...)` 生成，嘴巴状态通过 `AppContentContract.mouthStateLabel(...)` 得出。
- `DigitalDog/app/src/main/java/com/digitaldog/demo/petstage/PetStagePlaceholder.kt`
  - `isSpeakingMouthOpen = speechAnimationState.mouthOpen || petState == PetState.Speaking`。
  - 舞台渲染用 `displayMouth = MouthShape.Open` 表示讲话嘴；contentDescription 由 `AppContentContract.stageDescription(...)` 生成。
  - 不要把嘴巴状态改回时间轴驱动。
- `DigitalDog/app/src/main/java/com/digitaldog/demo/speechinput/SpeechInputPlaceholder.kt`
  - `TagTtsInputField`, `TagPrimaryTtsCta`, `TagSampleCta`, `TagQuickActions` 是 UI 测试稳定入口。
  - `isBusy` 同时禁用主 CTA 和示例入口；主 CTA busy 文案为 `PrimaryCtaBusy`。
  - `QuickActionsDescription`, `ttsInputDescription(...)`, `primaryTtsCtaDescription(...)` 都来自 `AppContentContract`。
- `DigitalDog/app/src/main/java/com/digitaldog/demo/statussummary/StatusSummaryPlaceholder.kt`
  - 只显示当前状态、嘴巴状态、输入来源；语义由 `statusSummaryDescription(...)` 生成。
  - 2.5 修复后，非 speaking 但 `currentMouth = Open` 的注入状态会显示 `MouthStateOpen`，讲话状态显示 `MouthStateTalking`。
