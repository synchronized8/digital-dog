# 头脑风暴会话结果

## 会话概览

**主题：** 数字狗网页 UI：语音驱动口型同步与虚拟宠物表现。

**目标：** 头脑风暴并细化一个网页虚拟宠物数字狗 demo：

- 不讲话时保持闭口待机状态。
- 讲话时使用多种嘴型模拟不同发音。
- 提供多种测试音频入口：上传音频、麦克风录音、文字转语音、内置示例音频。
- 增加表情和动作表现，包括头部、耳朵、眼睛、身体动画。
- 优先保证可爱、精致的视觉表现，以及相对准确的口型同步。
- 当前先作为视觉验证 demo，后续保留接入真实 AI 语音对话的路径。

### 会话设置

当前阶段重点是产品、交互和视觉方向的探索，不进入具体实现。关键开放问题包括视觉风格、口型同步精度、音频处理策略、测试控件、动画状态，以及未来 AI 对话架构需要在 demo 阶段预留到什么程度。

**流程设计：** 先从宽泛创意探索开始，再识别模式，随后发展具体概念，最后收敛成可执行计划。

- **阶段 3 - 概念发展：** 使用形态分析，把狗狗风格、嘴型系统、输入模式、表情层和调试控件组合成具体 demo 概念。
- **阶段 4 - 行动规划：** 使用决策树映射，把概念选择转成 MVP 实施路径。

## 阶段 1 - 扩散探索

**技巧：** What If 场景

**[交互 #1]：唤醒式宠物讲话循环**
_概念_：数字狗像一只被声音唤醒的小虚拟宠物。讲话前，耳朵竖起、眼睛看向用户、嘴巴准备张开；讲话中，嘴型跟随发音变化，头部轻微点动，身体保持呼吸节奏；讲话后，闭口、眨眼、摇尾，然后回到待机。
_新意_：讲话状态不只是嘴巴动画，而是一整套宠物行为循环。即使还没有接入真实 AI 对话，demo 也会显得更有生命感。

**[口型同步 #2]：七类狗狗嘴型集合**
_概念_：demo 支持一套推荐完整嘴型：闭口、小开口、大开口、圆嘴、咧嘴/e-i 嘴型、齿音/摩擦音嘴型、开心喘气/宠物表情嘴型。第一版可以先在视觉上提供全部 7 种嘴型，内部驱动则先用稳定的音频分析分组，后续再升级到更细的 viseme 或 phoneme 映射。
_新意_：在可爱表现和准确度之间取得平衡，让狗狗拥有清晰、可读的表达，不强迫第一版就解决完美语音识别。

**[UI #3]：宠物舞台 + 开发调试台**
_概念_：主 UI 像一个虚拟宠物舞台，数字狗是情绪中心；旁边或可折叠区域提供开发调试台，显示音频来源、波形、当前嘴型、viseme 状态、时序和延迟。上传、麦克风、TTS 和示例音频可以在表层包装成有趣的互动模式，技术细节则用于调试和校准。
_新意_：不在“可爱体验”和“工程调试”之间二选一，同一个 demo 既能做设计验证，也能做口型同步工程验证。

**[信息架构 #4]：首屏三信号**
_概念_：首屏必须立刻传达三件事：这是一只可互动的数字狗；它能跟随声音讲话并变嘴型；这里可以用多种方式测试音频输入。数字狗、讲话能力提示和输入控件都应在首屏可见，不做营销式落地页。
_新意_：让 demo 从第一屏就是可用体验，而不是用静态文案解释功能。

**[视觉设计 #5]：软萌宠物 + 轻科技项圈**
_概念_：数字狗首先应被感知为柔软、可爱的虚拟宠物，具备圆润形体、友好眼睛、轻柔待机动作和温暖情绪。轻科技项圈用于承载待机、聆听、讲话、思考、AI 就绪等状态光效，但不让狗狗变成冰冷机器人。
_新意_：技术层成为配件和反馈通道，而不是主导视觉身份。

**[动画 #6]：自然分层动作 + 关键可爱反馈**
_概念_：普通讲话时动画自然克制：嘴型是最高频动作层，头部跟随语句节奏轻动，耳朵和眼睛以较低频率响应，身体持续呼吸，尾巴主要用于讲话结束或测试成功反馈。可爱反应只在测试成功、讲话结束、用户互动等关键时刻出现，而不是全程乱动。
_新意_：数字狗显得有生命感且精致，同时不会干扰用户观察口型同步。

**[音频体验 #7]：分层音频输入体验**
_概念_：音频入口按演示稳定性分层：文字转语音作为主入口，内置示例音频作为一键演示的次入口，上传音频和麦克风录音作为实验入口。调试台显示每种来源的解析质量和当前嘴型状态。
_新意_：既保证演示时有稳定路径，也证明所有要求的音频输入方式都存在。

**[调试 #8]：口型同步准确度调试层**
_概念_：demo 提供非侵入式调试层，可显示当前嘴型标签、音频波形、嘴型时间轴、TTS 文本或音素高亮，以及简化版延迟校准控件。这些信息放在调试台中，保证宠物舞台仍然保持干净、可爱。
_新意_：口型准确度可以被观察和校准，同时不牺牲第一眼的情感体验。

**[未来集成 #9]：Mock AI 对话状态**
_概念_：即使还没有接入真实 AI，也要预留 AI 对话状态模型：聆听、思考、讲话、完成、错误/无输入。项圈、耳朵、眼睛、嘴巴和姿态都可以先通过 mock 事件响应这些状态，后续再接真实事件。
_新意_：提前验证情绪化对话循环，同时为未来 AI 语音系统保留清晰接入路径。

**[风险控制 #10]：Demo 失败防护栏**
_概念_：第一版 demo 必须规避常见失败模式：嘴型与声音不同步、嘴型乱跳、次级动画干扰口型观察、UI 过于玩具化或过于工具化、音频入口存在但不稳定、麦克风权限导致演示失败、TTS 计时与嘴型时间轴漂移、未来 AI 对话状态需要重构。这些风险应从 MVP 和测试计划阶段就开始影响设计。
_新意_：把 demo 同时当作视觉产品原型和技术验证工具，提高它在第一次展示之后继续有用的概率。

### 阶段 1 小结

第一轮发散已经形成清晰的第一版 demo 方向：一个软萌虚拟宠物数字狗作为首屏中心，通过文字转语音、内置示例、上传音频和麦克风录音测试讲话表现；讲话时使用 7 类嘴型，并由头部、耳朵、眼睛、身体和尾巴形成自然克制的辅助动作；界面同时提供口型同步调试能力，并为未来 AI 语音对话预留状态机。

## 阶段 2 - 模式识别

**技巧：** 思维导图

**中心主题：** 数字狗语音口型同步网页 demo

### 一级模块归类

#### 1. 宠物身份与情绪循环

**关联想法：** 唤醒式宠物讲话循环、Mock AI 对话状态、软萌宠物 + 轻科技项圈

**核心模式：**

- 数字狗不是普通头像，而是一个有状态、有反应的虚拟宠物。
- 讲话行为应包含“讲话前、讲话中、讲话后”的完整情绪循环。
- 未来 AI 对话状态可以复用同一套宠物状态模型。

**关键状态：**

- `idle`：闭口、呼吸、偶尔眨眼。
- `preparing/listening`：耳朵竖起、眼睛看向用户、项圈亮起。
- `thinking`：嘴巴闭合、项圈呼吸光、轻微歪头。
- `speaking`：嘴型同步、头部轻动、身体前倾。
- `done`：闭口、眨眼、尾巴轻摇。
- `error/no input`：疑惑表情、歪头、项圈提示色。

#### 2. 口型同步系统

**关联想法：** 七类狗狗嘴型集合、口型同步准确度调试层、Demo 失败防护栏

**核心模式：**

- 视觉层保留 7 类嘴型，让表达丰富可读。
- 驱动层第一版不追求完美语音识别，而是根据输入类型采用不同精度策略。
- TTS 是最适合做准确口型演示的主路径，上传和麦克风作为实验路径。

**嘴型集合：**

- `closed`：闭口、静音、停顿、m/b/p 类闭唇音。
- `small`：小开口、轻声、普通短音。
- `wide`：大开口、重音、a/ah 类元音。
- `round`：圆嘴、o/u 类音。
- `smile`：咧嘴、e/i 类音。
- `teeth`：齿音或摩擦音，如 f/v/s/th 的视觉提示。
- `pant`：开心喘气或宠物式表达。

#### 3. 音频输入与演示路径

**关联想法：** 分层音频输入体验、首屏三信号、宠物舞台 + 开发调试台

**核心模式：**

- 所有音频入口都要有，但不能在视觉优先级上平等。
- 文字转语音承担“最稳定演示路径”。
- 内置示例音频承担“一键看效果”。
- 上传音频和麦克风录音承担“覆盖真实输入场景”的实验能力。

**推荐优先级：**

- 主入口：文字转语音。
- 次入口：内置示例音频。
- 实验入口：上传音频、麦克风录音。
- 调试反馈：每种输入来源都显示解析质量和当前嘴型状态。

#### 4. 首屏 UI 与信息架构

**关联想法：** 首屏三信号、宠物舞台 + 开发调试台、分层音频输入体验

**核心模式：**

- 第一屏不做营销介绍页，而是直接呈现可用 demo。
- 用户必须立刻看懂三件事：这是一只可互动的数字狗；它会跟随声音讲话并变嘴型；这里可以用多种方式测试音频输入。
- 主体验和调试能力并存，但视觉中心必须是数字狗。

**首屏结构：**

- 中央或主区域：数字狗宠物舞台。
- 主操作区：文字转语音输入与“让狗狗说话”按钮。
- 快速演示区：内置示例音频。
- 实验入口区：上传音频、麦克风录音。
- 调试区：嘴型、波形、时间轴、延迟校准。

#### 5. 视觉风格与动作层

**关联想法：** 软萌宠物 + 轻科技项圈、自然分层动作 + 关键可爱反馈、唤醒式宠物讲话循环

**核心模式：**

- 主视觉是软萌宠物，不是冷科技机器人。
- 科技感通过项圈、状态光和调试 UI 表达。
- 动作要自然克制，关键时刻给可爱反馈。

**动作层级：**

- 嘴巴：最高频，跟随口型状态变化。
- 头部：中频，跟随语句节奏轻微点动。
- 耳朵：低频，讲话前竖起，重点时轻弹。
- 眼睛：低频，看向用户，停顿时眨眼。
- 身体：持续呼吸，讲话时轻微前倾。
- 尾巴：完成、成功或互动反馈时摇动。

#### 6. 调试、校准与可信度

**关联想法：** 口型同步准确度调试层、Demo 失败防护栏、宠物舞台 + 开发调试台

**核心模式：**

- Demo 不只要看起来可爱，也要能判断“准不准”。
- 调试能力应放在控制台区域，避免污染宠物舞台。
- 第一版要有简单但明确的准确度反馈和延迟校准。

**调试内容：**

- 当前嘴型标签。
- 音频波形。
- 嘴型时间轴。
- TTS 文本或音素高亮。
- 简化延迟校准。
- 输入来源与解析质量。

#### 7. 风险与边界

**关联想法：** Demo 失败防护栏、分层音频输入体验、Mock AI 对话状态

**核心模式：**

- 第一版要优先保证可演示性，不把最不稳定的路径放到最显眼的位置。
- 麦克风权限、上传音频解析、TTS 时间漂移等风险需要被 UI 和调试设计吸收。
- AI 对话状态先 mock，不阻塞视觉和口型 demo。

**主要风险：**

- 口型与声音不同步。
- 嘴型切换过快或乱跳。
- 辅助动作干扰口型观察。
- UI 太玩具化，看不出工程调试能力。
- UI 太工具化，削弱宠物情感。
- 四种输入入口都存在但都不稳定。
- 麦克风权限影响演示。
- 未来 AI 接入需要重构状态机。

### 模式识别结论

当前想法可以收敛成一个核心产品结构：**一个以软萌数字狗为中心的可交互语音口型 demo，外层是宠物舞台，内层是口型同步引擎和调试控制台，底层预留 AI 对话状态机。**

这意味着第一版 demo 不应该平均建设所有能力，而应该优先打磨三条主线：

- **视觉主线：** 软萌宠物、轻科技项圈、自然分层动作。
- **口型主线：** 7 类嘴型、TTS 优先驱动、可观察时间轴。
- **演示主线：** 首屏可用、TTS 主入口、示例音频兜底、上传和麦克风作为实验入口。

## 阶段 3 - 概念发展

**技巧：** 形态分析

**目标：** 把前面归类出的模块组合成 2-3 个具体 demo 方案，并选出第一版 MVP。

### 形态分析维度

| 维度 | 可选方向 |
| --- | --- |
| 首屏重心 | 宠物舞台优先 / 调试台优先 / 对话流程优先 |
| 主演示入口 | 文字转语音 / 内置示例音频 / 麦克风录音 / 上传音频 |
| 口型驱动策略 | TTS 文本估算 viseme / 音频音量频谱驱动 / 手动时间轴 / 混合驱动 |

| 动作层级 | 只动嘴 / 嘴 + 头眼耳 / 全身分层动作 |
| 调试深度 | 当前嘴型标签 / 波形 + 时间轴 / 文本高亮 + 延迟校准 |

| 演示稳定性 | 高稳定演示 / 多入口覆盖 / 真实对话预览 |

### 方案 A：TTS 精准演示宠物舞台

**定位：** 第一版最推荐的 MVP 方案。优先证明“这只数字狗可爱，并且口型能比较准确地跟着语音走”。

**组合方式：**

- 首屏重心：宠物舞台优先，调试台作为右侧或底部辅助区。
- 主演示入口：文字转语音。
- 次入口：内置示例音频。
- 实验入口：上传音频、麦克风录音保留，但视觉优先级较低。
- 口型驱动策略：TTS 文本估算 viseme + 音量节奏修正。
- 嘴型复杂度：7 类完整嘴型。
- 动作层级：嘴 + 头眼耳 + 呼吸 + 结束摇尾。
- 调试深度：当前嘴型标签、波形、嘴型时间轴、TTS 文本高亮、简化延迟校准。
- AI 预留：可视化 mock 状态机，但不作为主流程。

**首屏体验：**

用户打开页面后，中央看到软萌数字狗，项圈处于待机光效。用户在文字输入框输入一句话，点击“让狗狗说话”，数字狗先耳朵竖起、看向用户，然后开始讲话；嘴型按 7 类 viseme 切换，头部轻微点动，身体保持呼吸。调试台同步显示文本高亮、当前嘴型、波形和嘴型时间轴。

**优势：**

- 最容易稳定演示。
- 最能体现口型准确度。
- 最符合“可爱好看 + 口型同步准确”的核心目标。
- 后续可自然扩展上传、麦克风和 AI 对话。

**风险：**

- 上传音频和麦克风第一版可能只是实验能力，不是最强亮点。
- 如果 TTS 使用浏览器原生能力，语音质量和时间控制可能受浏览器影响。

**适合做第一版 MVP：** 是。

### 方案 B：全输入口型实验室

**定位：** 偏工程验证。优先证明四种音频入口都能驱动口型。

**组合方式：**

- 首屏重心：调试台和输入入口更突出，宠物舞台仍然可见。
- 主演示入口：四种入口平铺展示。
- 口型驱动策略：上传和麦克风主要通过音量、频谱和节奏驱动；TTS 走文本估算。
- 嘴型复杂度：7 类嘴型，但真实音频入口可能降级到 4-5 类稳定状态。
- 动作层级：口型为主，其他动作克制。
- 调试深度：强调波形、频谱、解析质量、嘴型切换时间轴。
- AI 预留：仅保留状态字段。

**首屏体验：**

用户像进入一个口型同步测试台，可以选择 TTS、示例、上传、麦克风任一入口。数字狗会响应所有输入，但界面更强调分析状态和输入质量。

**优势：**

- 覆盖完整输入要求。
- 有利于验证真实音频的口型驱动边界。
- 技术可信度强。

**风险：**

- 第一眼可爱感较弱。
- 多入口同时打磨会分散精力。
- 麦克风权限、上传音频质量、浏览器兼容会增加 demo 翻车概率。

**适合做第一版 MVP：** 不建议作为第一版主方案，可作为第二阶段增强。

### 方案 C：AI 对话预览宠物

**定位：** 偏产品愿景。优先让用户感到“这是一只未来可以真实聊天的数字狗”。

**组合方式：**

- 首屏重心：对话状态流程优先。
- 主演示入口：麦克风按钮或 mock 对话按钮。
- 次入口：TTS 用于播放数字狗回答。
- 口型驱动策略：预设回答文本 + TTS viseme 驱动。
- 嘴型复杂度：7 类嘴型。
- 动作层级：完整情绪状态，重点展示 listening、thinking、speaking、done、error。
- 调试深度：较轻，只显示当前状态和嘴型标签。
- AI 预留：完整 mock 状态机作为核心体验。

**首屏体验：**

用户点击“开始对话”，数字狗进入聆听状态，随后进入思考，再用预设回答讲话。整体像 AI 语音宠物的未来演示。

**优势：**

- 产品想象力强。
- 更容易展示情绪循环和未来 AI 接入价值。
- 数字狗更像真实陪伴型宠物。

**风险：**

- 当前目标里的多音频输入和口型调试会被弱化。
- 如果没有真实 AI，可能显得像流程动画，而不是口型同步 demo。
- 口型准确度验证不如方案 A 直接。

**适合做第一版 MVP：** 不建议作为第一版主方案，可作为第一版中的“AI 状态预览模式”保留。

### 第一版 MVP 选择

**推荐选择：方案 A：TTS 精准演示宠物舞台。**

选择理由：

- 它最直接服务当前最高优先级：**可爱好看 + 口型同步准确**。
- TTS 是最稳定的演示入口，能让 7 类嘴型和文本高亮形成可验证闭环。
- 内置示例音频可以作为兜底，保证打开页面后一键看到效果。
- 上传音频和麦克风不会被删除，只是作为实验入口降低首屏优先级，避免第一版被不稳定输入拖慢。
- Mock AI 状态机可以内置在宠物状态层，不抢主流程，但后续接真实 AI 时不需要重构。

### 口型驱动策略

#### 视觉嘴型层

7 类嘴型全部需要有明确视觉差异：

- `closed`：嘴线闭合，静音和停顿使用。
- `small`：小开口，普通短音使用。
- `wide`：大开口，重音和响亮元音使用。
- `round`：圆嘴，o/u 类感觉使用。
- `smile`：横向咧嘴，e/i 类感觉使用。
- `teeth`：轻微露齿或咬合，f/s/v 等摩擦音感觉使用。
- `pant`：开心喘气，宠物反馈和非语言表达使用。

#### TTS 主路径

第一版推荐使用“文本估算 + 时间轴播放”：

- 将输入文本切分成字符、词或近似音节。
- 根据字符/拼音/英文字符规则映射到 7 类嘴型。
- 按文本长度生成嘴型时间轴。
- 播放 TTS 时按时间轴切换嘴型。
- 用音量节奏或预设节奏调整 `small` / `wide` 的强弱。
- 文本高亮与嘴型时间轴共用同一套进度。

#### 示例音频路径

第一版推荐使用“预设时间轴 + 音频播放”：

- 内置一条稳定示例音频。
- 为示例音频配置一条嘴型时间轴。
- 播放时显示波形和时间轴，保证演示稳定。

#### 上传与麦克风路径

第一版推荐使用“音频分析降级驱动”：

- 分析音量包络，识别静音、轻声、重音。
- 用频谱粗略区分圆嘴倾向和齿音倾向。
- 无法判断时在 `small`、`wide`、`closed` 间稳定切换。
- 明确显示解析质量，避免用户误以为已达到 TTS 同等准确度。

### 动画实施策略

#### 优先级

1. 嘴型切换准确、稳定。
2. 头部轻微跟随讲话节奏。
3. 呼吸和眨眼保持生命感。
4. 耳朵用于准备和重点反馈。
5. 尾巴用于讲话完成和测试成功。

#### 动画约束

- 讲话时辅助动作幅度要小，不能抢嘴型注意力。
- 嘴型切换要有短过渡，避免乱跳。
- 静音段必须回到 `closed`，强化“没讲话就是闭口”。
- 错误反馈要可爱但短暂，不要阻塞下一次测试。

### 实施顺序

#### 第 1 步：搭建静态首屏

- 建立宠物舞台、主输入区、四种音频入口、调试台布局。

**验收：** 不接音频也能完整演示状态切换。

#### 第 3 步：实现 7 类嘴型和手动测试

- 调试台提供当前嘴型标签。
- 提供手动切换嘴型的开发测试能力。

**验收：** 每个嘴型可被单独触发，视觉上明显不同且不违和。

- 文本输入触发 TTS 或模拟 TTS。

- 显示当前嘴型。

**验收：** 用户能判断当前嘴型是否跟音频/文本同步。

#### 第 6 步：接入示例音频

- 内置一条稳定示例音频。

- 麦克风录音后可回放并驱动基础口型。
- 权限失败或解析失败进入 `error` 状态。

**验收：** 两个实验入口都可用，并明确显示解析质量。

#### 第 8 步：打磨可爱反馈和风险边界

- 优化耳朵、眨眼、呼吸、尾巴反馈。
- 控制讲话时辅助动作幅度。
- 检查错误状态、空输入、权限失败、移动端布局。

**验收：** demo 看起来像一个完整产品原型，而不是功能拼接。
