# 数字狗可爱讲话动画 Demo - UI 规格

**创建日期：** 2026-06-23
**更新日期：** 2026-06-25
**状态：** 当前执行版
**来源：** `docs/MVP-SPEC.md`、`docs/planning-artifacts/epics.md`
**UI 方向：** 软萌宠物 + 简洁输入 + 轻量状态摘要

## UI 目标

第一屏就是可使用的小狗讲话动画 demo。用户拿到 Redmi Pad SE 后，应立即看到一只可爱小狗，并能通过文本或示例让它讲话。

当前 UI 不展示复杂调试台；只保留轻量状态摘要，让用户知道当前是待机、准备、讲话、完成或错误。

## 当前信息架构

1. 顶部状态栏。
2. 小狗宠物舞台。
3. 主输入区：文本输入 + `让狗狗说话`。
4. 示例入口：`播放示例`。
5. 轻量状态摘要：当前状态、输入来源、嘴巴状态。
6. 错误与恢复反馈。

当前首屏不包含上传音频、麦克风录音、波形、嘴型时间轴、文本高亮或延迟校准。

## 设计原则

- **宠物优先**：小狗是主角，输入和状态摘要服务于互动。
- **直接可用**：不做营销页，不用大段说明文字。
- **可爱但克制**：软萌形体、自然动作、短反馈，避免过度玩具化。
- **专业但不工具化**：状态清晰，但不把首屏做成调试控制台。
- **布局稳定**：播放中按钮、标签、状态摘要和舞台尺寸不跳动。
- **可访问**：颜色必须配合文字或标签表达；核心控件支持 TalkBack 和键盘焦点。

## Redmi Pad SE 横屏布局

适用尺寸：1920 x 1200 / 16:10 横屏视口，以及 Android 系统缩放后的等价逻辑视口。

```text
+----------------------------------------------------------------+
| 顶部状态栏：Digital Dog Demo / 当前状态 / 输入来源 / 嘴巴状态  |
+----------------------------------------------------------------+
|                                                                |
|                         小狗宠物舞台                            |
|                  小狗居中，嘴巴区域清晰可见                    |
|                                                                |
+----------------------------------------------------------------+
| 文本输入：输入一句想让狗狗说的话                               |
| [让狗狗说话] [播放示例]              状态摘要 / 错误反馈        |
+----------------------------------------------------------------+
```

布局要求：

- 小狗舞台占主要高度，输入区固定在底部或舞台下方。
- 状态摘要不能遮挡嘴巴区域。
- 主 CTA 视觉权重最高，示例入口为次级。
- 横屏下不出现右侧复杂调试栏。

## Redmi Pad SE 竖屏布局

适用尺寸：1200 x 1920 / 10:16 竖屏视口，以及 Android 系统缩放后的等价逻辑视口。

```text
+--------------------------------+
| 顶部状态栏                      |
+--------------------------------+
|                                |
|          小狗宠物舞台            |
|                                |
+--------------------------------+
| 文本输入                        |
| [让狗狗说话] [播放示例]          |
| 状态摘要 / 错误反馈              |
+--------------------------------+
```

布局要求：

- 小狗舞台优先展示，不被输入区挤到过小。
- 按钮可一行或两行排列，但文字不得溢出。
- 状态摘要可换行，但不得与按钮重叠。
- 不展示折叠调试台入口。

## 设计系统

| 属性 | 规格 |
| --- | --- |
| 组件库 | Jetpack Compose 原生组件优先，宠物舞台和小狗形象可自定义绘制 |
| 图标库 | Material Icons 或 Compose Icons 优先 |
| 字体 | Android 系统字体、`Roboto`、`Noto Sans CJK`，可按 MIUI 实机字体替换 |
| 卡片圆角 | 8px |
| 按钮圆角 | 8px |
| 输入框圆角 | 8px |
| 触控目标 | 不小于 48dp |
| 装饰 | 不使用渐变球、散景圆点或纯装饰性光斑 |

| Token | Value | 用途 |
| --- | --- | --- |
| `xs` | 4px | 图标与文字间距、紧凑内部间距 |
| `sm` | 8px | 按钮组、标签组、小组件间距 |
| `md` | 16px | 常规组件间距 |
| `lg` | 24px | 主区域间距 |
| `xl` | 32px | 横屏大区域间距 |

### 字体

| 角色 | 横屏 | 竖屏 | 字重 | 行高 |
| --- | --- | --- | --- | --- |
| 页面标题 | 24px | 20px | 700 | 1.25 |
| 区块标题 | 16px | 15px | 650 | 1.3 |
| 正文 | 14px | 14px | 400 | 1.5 |

约束：

- 字号不随视口宽度线性缩放。
- 字间距为 `0`。
- 按钮、标签和状态摘要文字必须完整可读，不得重叠或裁切。

## 组件规格

### 顶部状态栏

用途：显示 demo 名称、当前状态、输入来源和嘴巴状态。

内容：

- 标题：`Digital Dog Demo`
- 状态标签：`待机`、`准备中`、`讲话中`、`完成`、`需要处理`
- 输入来源：`文本`、`示例`
- 嘴巴状态：`闭口`、`讲话嘴`

状态点颜色必须配合文字，不得只靠颜色表达。

### 小狗宠物舞台

用途：承载小狗形象和主要情绪表现。

内容：

- 小狗主体。
- 轻科技项圈。
- 简洁舞台地面或窝垫。
- 可选短状态标签，但不能遮挡嘴巴。

布局要求：

- 横屏小狗可视高度建议占舞台高度 65% 到 78%。
- 竖屏小狗不得被压缩到难以观察嘴巴。
- 舞台不得放入多层嵌套卡片。
- 嘴巴区域必须清晰可见。

### 小狗形象

必备部位：

- 眼睛：看向用户、眨眼、疑惑。
- 耳朵：竖起、轻弹、回落。
- 嘴巴：闭口、讲话嘴或轻微开合循环。
- 头部：轻微点头、歪头。
- 身体：呼吸、低幅度律动。
- 尾巴：完成和成功反馈。
- 项圈：状态光。

当前 MVP 不要求 7 类嘴型。当前 production 只保留闭口和张口两种嘴巴状态，默认 UI 不暴露手动嘴型测试。

### 主输入区

用途：文本主路径。

内容：

- 文本输入框。
- 主按钮：`让狗狗说话`。
- 输入状态提示。

交互：

- 空文本点击主按钮进入 `error`。
- 非空文本点击主按钮进入准备状态，随后进入 `speaking`。
- 播放中主按钮变为 `讲话中`、`停止` 或禁用，避免重复触发。

文案：

- Placeholder：`输入一句想让狗狗说的话`
- 主 CTA：`让狗狗说话`
- 播放中：`讲话中`
- 空输入错误：`先输入一句话`

### 示例入口

用途：提供稳定演示路径。

控件：

- `播放示例`

交互：

- 点击后触发与文本路径相同的小狗讲话流程。
- 播放中禁用或切换为停止状态。
- 示例入口不得请求麦克风权限。

### 轻量状态摘要

用途：替代旧调试台，展示最小可理解状态。

内容：

- 当前状态。
- 输入来源。
- 嘴巴状态。
- 可恢复错误提示。

限制：

- 不展示波形。
- 不展示嘴型时间轴。
- 不展示 TTS 文本高亮。
- 不展示延迟校准。
- 不展示解析质量调试面板。

### 错误反馈

用途：让用户知道如何恢复。

空文本错误：

- 文案：`先输入一句话`
- 小狗表现：闭口、疑惑或轻微歪头。
- 项圈：提示黄。

忙碌重复触发：

- 主按钮禁用或显示播放中状态。
- 不出现第二个冲突讲话流程。

## 动效契约

| 动作 | 建议时长 | 当前 MVP 要求 |
| --- | --- | --- |
| 嘴巴开合 | 80ms 到 180ms | `speaking` 时可观察到开合 |
| 眨眼 | 120ms 到 180ms | 待机或完成反馈可用 |
| 耳朵竖起 | 180ms 到 260ms | 准备阶段可用 |
| 头部点动 | 180ms 到 320ms | 讲话中低幅度使用 |
| 呼吸 | 2400ms 到 3600ms | 待机生命感 |
| 尾巴反馈 | 500ms 到 900ms | 完成后一次短反馈 |
| 错误歪头 | 300ms 到 450ms | 空文本错误可用 |

减少动态策略：

- 保留讲话嘴巴开合。
- 降低耳朵、头部、身体和尾巴装饰动作。
- 不因减少动态移除状态文字和错误反馈。

## 可访问性

- 小狗图形可作为装饰，但当前状态和嘴巴状态必须可被 TalkBack 获取。
- 文本输入、主 CTA、示例入口和错误反馈必须可聚焦。
- 状态颜色必须配合文字、标签、图标或位置表达。
- 按钮和输入控件触控目标不小于 48dp。
- 键盘焦点顺序：顶部状态、小狗状态、文本输入、主 CTA、示例入口、状态摘要、错误反馈。

## 默认 UI 不出现的内容

以下内容移出当前 MVP，不应出现在默认 UI：

- 上传音频。
- 麦克风录音。
- 波形。
- 嘴型时间轴。
- TTS 文本高亮。
- 延迟校准。
- 完整调试台。
- 解析质量面板。

后续如需恢复，必须通过新的 scope change 和单独 UI 规格补充。

## UI 验收清单

- [ ] 横屏首屏小狗舞台是视觉中心。
- [ ] 竖屏核心控件不重叠、按钮文字不溢出。
- [ ] 文本输入、主 CTA 和示例入口首屏可见。
- [ ] `speaking` 时嘴巴张口或轻微开合。
- [ ] 非 `speaking` 状态嘴巴闭合。
- [ ] 状态摘要显示当前状态、输入来源和嘴巴状态。
- [ ] 空文本错误靠近输入区，并可恢复。
- [ ] 默认 UI 不展示 deferred 调试或音频入口。
- [ ] TalkBack 能读出当前状态、输入来源、嘴巴状态和错误原因。
- [ ] 减少动态时仍能观察讲话嘴。
