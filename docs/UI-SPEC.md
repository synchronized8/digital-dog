# 数字狗语音口型 Demo — UI 规格

**创建日期：** 2026-06-23  
**状态：** 草稿  
**来源：** `docs/MVP-SPEC.md`、`docs/brainstorming/brainstorming-session-20260623-144420.md`  
**UI 方向：** 软萌宠物 + 轻科技项圈 + 宠物舞台优先 + 调试台辅助

**2026-06-24 平台纠偏：** 第一版展示设备更正为小米 Redmi Pad SE 11 英寸 MIUI / Android 平板。本文中的 iPad / iPadOS 表述均按 Redmi Pad SE / Android 原生平板方案解释；横屏主验收按 1920 x 1200 / 16:10，竖屏按 1200 x 1920。

## UI 目标

第一屏就是可使用的 Redmi Pad SE 展示 demo。用户拿到平板后应立即看到一只可互动数字狗，并能通过文字、示例音频、上传音频或麦克风录音触发讲话表现；调试台用于观察口型同步准确度，但不能抢走数字狗的视觉中心。

## 设计原则

- **宠物优先**：数字狗是主角，调试控件是辅助。
- **可爱但不幼稚**：软萌形体、自然动作、克制反馈，避免过度玩具化。
- **专业但不冰冷**：保留嘴型、波形、时间轴、延迟校准等调试能力。
- **首屏可用**：不做营销式介绍页，不用大段说明文字。
- **稳定演示**：TTS 和内置示例是主演示路径，上传和麦克风是实验入口。
- **动作克制**：讲话时嘴型优先，头、耳、眼、身体和尾巴只做辅助。

### 顶层区域

1. 顶部状态栏
2. 宠物舞台
3. 调试台

### Redmi Pad SE 横屏布局

适用尺寸：1920 x 1200 / 16:10 横屏视口，以及 Android 系统缩放后的等价逻辑视口。

```text
+----------------------------------------------------------------+
| 顶部状态栏：Digital Dog Demo / 当前状态 / 当前输入来源         |
+--------------------------------+-------------------------------+
|                                |                               |
|          宠物舞台               |            调试台              |
|       数字狗居中展示            |   当前嘴型 / 波形 / 时间轴     |
|       状态光效与动作            |   文本高亮 / 延迟校准          |
|                                |                               |
+--------------------------------+-------------------------------+
| 主输入区：文本输入 + 让狗狗说话                                |
| 快速入口：播放示例 / 上传音频 / 麦克风录音                      |
+----------------------------------------------------------------+
```

**布局比例：**

- 宠物舞台：主内容宽度约 60%。
- 调试台：主内容宽度约 40%。
- 下方输入区跨全宽。
- 内容区在横屏下应充分利用 iPad 宽度，但保留安全边距，避免控件贴近屏幕边缘。

### Redmi Pad SE 竖屏布局

适用尺寸：1200 x 1920 / 10:16 竖屏视口，以及 Android 系统缩放后的等价逻辑视口。

- 宠物舞台置顶，占主要高度。
- 调试台位于宠物舞台下方，可展开。
- 主输入区紧跟宠物舞台。
- 快速入口使用两列网格。

- 数字狗不可被调试台挤到过小。
- 调试台默认折叠，只露出当前嘴型和状态摘要。
- 按钮文本不得溢出；必要时图标 + 短标签。

## 组件规格

### 1. 顶部状态栏

**用途：** 显示 demo 名称、宠物状态、输入来源。

**内容：**

- 标题：`Digital Dog Demo`
- 状态标签：`待机`、`聆听`、`思考`、`讲话中`、`完成`、`需要处理`
- 输入来源：`TTS`、`示例音频`、`上传音频`、`麦克风`

**状态：**

- `idle`：低对比状态点。
- `listening`：蓝色状态点。
- `thinking`：蓝色呼吸状态点。
- `speaking`：珊瑚状态点。
- `done`：绿色状态点。
- `error`：黄色状态点。

### 2. 宠物舞台

**用途：** 承载数字狗形象和主要情绪表现。

**内容：**

- 数字狗主体。
- 轻科技项圈。
- 简洁舞台地面或窝垫。
- 可选状态小标签，但不能遮挡嘴巴。

**布局要求：**

- iPad 横屏数字狗可视高度建议占舞台高度 65% 到 78%。
- 舞台不得放入多层嵌套卡片。
- 嘴巴区域必须清晰可见，不被调试控件覆盖。

### 3. 数字狗形象

**风格：**

- 软萌虚拟宠物。
- 圆润头部和身体。
- 友好大眼睛。
- 嘴巴区域可清晰变形。
- 项圈表达轻科技感。

**必备部位：**

- 眼睛：看向用户、眨眼、疑惑。
- 耳朵：竖起、轻弹、回落。
- 嘴巴：7 类嘴型。
- 头部：轻微点头、歪头。
- 身体：呼吸、轻微前倾。
- 尾巴：完成和成功反馈。
- 项圈：状态光。

### 4. 主输入区

**用途：** TTS 主路径。

**内容：**

- 文本输入框。
- 主按钮：`让狗狗说话`
- 输入状态提示。

**交互：**

- 空文本点击主按钮进入 `error`。
- 有文本点击主按钮进入 `thinking`，随后进入 `speaking`。
- 播放中主按钮变为 `停止` 或禁用，避免重复触发。

**文案：**

- Placeholder：`输入一句想让狗狗说的话`
- 主 CTA：`让狗狗说话`
- 播放中：`讲话中`
- 空输入错误：`先输入一句话`

### 5. 快速音频入口

**用途：** 示例、上传、麦克风入口。

**控件：**

- `播放示例`
- `上传音频`
- `开始录音` / `停止录音`

**优先级：**

- `播放示例` 比上传和麦克风更突出。
- 上传和麦克风标记为实验入口，但不使用冗长说明。

### 6. 调试台

**用途：** 展示口型同步可信度。

**内容：**

- 当前嘴型标签。
- 当前状态。
- 当前输入来源。
- 解析质量：`稳定`、`一般`、`实验`。
- 音频波形。
- 嘴型时间轴。
- TTS 文本高亮。
- 延迟校准。

**布局：**

- iPad 横屏固定在宠物舞台右侧。
- iPad 竖屏默认折叠，摘要显示当前嘴型和状态。
- 调试台不能遮挡宠物舞台。

### 7. 波形组件

**用途：** 表示音频能量。

**规格：**

- 高度：iPad 横屏 72pt，iPad 竖屏 56pt。
- 使用柱状或折线均可。
- 当前播放进度用强调色显示。
- 静音段可见低能量。

### 8. 嘴型时间轴

**用途：** 显示每段时间对应的嘴型。

**规格：**

- 每个片段显示嘴型短名：`closed`、`small`、`wide`、`round`、`smile`、`teeth`、`pant`。
- 当前片段高亮。
- 延迟校准影响播放指针位置。
- 时间轴片段高度固定，避免播放时布局抖动。

### 9. TTS 文本高亮

**用途：** 让用户理解文字与嘴型进度的关系。

**规格：**

- 当前字符、词或近似音节高亮。
- 已播放部分低调着色。
- 未播放部分保持普通文字。
- 文本区域高度固定或可滚动，避免内容增长挤压宠物舞台。

### 10. 延迟校准

**用途：** 调整嘴型相对音频的偏移。

**控件：**

- 范围：`-150ms` 到 `+150ms`。
- 步进：`25ms`。
- 显示当前值，例如 `+50ms`。

**交互：**

- 调整后影响后续播放或当前时间轴指针。
- 默认值为 `0ms`。

## 状态与动效契约

### 状态视觉映射

| 状态 | 嘴型 | 眼睛 | 耳朵 | 身体 | 尾巴 | 项圈 |
| --- | --- | --- | --- | --- | --- | --- |
| `idle` | `closed` | 偶尔眨眼 | 自然回落 | 轻微呼吸 | 静止 | 低亮 |
| `listening` | `closed` | 看向用户 | 竖起 | 微前倾 | 静止 | 蓝光 |
| `thinking` | `closed` | 轻眨或上看 | 微动 | 轻微歪头 | 静止 | 呼吸光 |
| `speaking` | 7 类切换 | 看向用户 | 轻弹 | 轻微前倾和呼吸 | 基本静止 | 珊瑚或蓝光 |
| `done` | `closed` | 眨眼 | 回落 | 回正 | 轻摇 | 绿光 |
| `error` | `closed` | 疑惑 | 一侧轻垂 | 歪头 | 静止 | 黄光 |

### 动效时间

| 动作 | 时长 | 约束 |
| --- | --- | --- |
| 嘴型切换 | 80ms 到 140ms | 过渡短，不拖慢发音 |
| 眨眼 | 120ms 到 180ms | 不在每次嘴型变化时触发 |
| 耳朵竖起 | 180ms 到 260ms | 讲话前触发 |
| 头部点动 | 180ms 到 320ms | 跟随语句节奏，幅度小 |
| 呼吸 | 2400ms 到 3600ms 循环 | 始终低幅度 |
| 尾巴完成反馈 | 500ms 到 900ms | 讲话结束后一次短反馈 |
| 错误歪头 | 300ms 到 450ms | 短暂，不阻塞后续操作 |

### 动效约束

- 讲话时嘴型优先级最高。
- 辅助动作不得造成嘴巴区域位移过大。
- 口型切换需要最短保持时间，避免高频乱跳。
- 静音和停顿必须回到 `closed`。

## 口型视觉契约

| 嘴型 | 形状 | 使用场景 |
| --- | --- | --- |
| `closed` | 一条柔和嘴线 | 静音、停顿、待机 |
| `small` | 小椭圆或小弧形开口 | 普通短音 |
| `wide` | 纵向大开口 | 重音、响亮元音 |
| `round` | 圆形开口 | o/u 类声音 |
| `smile` | 横向咧嘴 | e/i 类声音 |
| `teeth` | 轻微露齿或咬合 | f/s/v 类声音感觉 |
| `pant` | 开心喘气嘴型 | 结束反馈或宠物表达 |

## 可访问性

- 所有按钮必须有可读文本或可访问标签。
- 麦克风、上传、播放状态变化需要通过可见状态文本和 VoiceOver 可读状态体现。
- 调试图表不能只依赖颜色，当前片段还需要位置或标签变化。
- 主 CTA、上传、录音、示例入口可通过触控、外接键盘和 VoiceOver 操作。
- 错误消息需要在视觉上靠近相关入口。
- 颜色对比度应满足普通正文至少 4.5:1。

## UI 验收清单

- [ ] 首屏不是营销页，而是可操作 demo。
- [ ] 数字狗是视觉中心，调试台是辅助。
- [ ] 文本输入、示例、上传、麦克风入口都可见。
- [ ] TTS 主入口在视觉优先级上最高。
- [ ] 7 类嘴型视觉差异明确。
- [ ] 静音和待机时嘴巴闭合。
- [ ] 状态变化能通过项圈、耳朵、眼睛、身体和尾巴体现。
- [ ] 讲话时辅助动作不干扰嘴型观察。
- [ ] 调试台显示当前嘴型、波形、时间轴、文本高亮和延迟校准。
- [ ] iPad 横屏和竖屏无控件重叠、无按钮文字溢出。
- [ ] 错误状态可见且可恢复。
- [ ] 整体色彩不是单一色相，软萌和轻科技都能被感知。
