# PRD：数字狗可爱讲话动画 Demo

## 0. 文档目的

本文档定义当前 MVP 的产品需求、用户场景、功能范围、非目标、成功指标和定稿决策。UI 细节以 `docs/UI-SPEC.md` 为准，实施拆分以 `docs/planning-artifacts/epics.md` 为准。

## 0.1 平台决策

第一版展示设备为 **小米 Redmi Pad SE 11 英寸 MIUI / Android 平板**。实现方向为 Android 原生应用，Kotlin + Jetpack Compose。本文不再使用旧 iPadOS / SwiftUI / AVFoundation 方案作为当前执行口径。

## 0.2 MVP 范围重置

2026-06-25 起，当前 MVP 从“精确口型同步 Demo”简化为“可爱小狗讲话动画 UI”。

新的 MVP 只要求：

- 用户通过文本主入口或示例入口触发小狗讲话动画。
- 小狗未讲话、待机、思考、错误和完成后必须闭口。
- 小狗讲话时必须张口或轻微开合，形成可观察的讲话嘴。
- 讲话嘴不需要与文本、音素、声音节奏或时间轴精确对齐。
- 讲话前、讲话中和讲话后需要少量俏皮但克制的动作，例如耳朵竖起、歪头、眨眼、轻微身体律动或摇尾。
- 首屏重点是小狗舞台、文本输入、`让狗狗说话` 和 `播放示例`；调试信息降级为轻量状态摘要。

以下旧能力移出当前 MVP：7 类嘴型覆盖目标、`LipSyncTimeline` 强制路径、TTS 文本高亮、波形、嘴型时间轴可视化、延迟校准、上传音频、麦克风录音、音频分析和高精度口型同步。

## 1. 愿景

数字狗 Demo 是一个 Redmi Pad SE / Android 平板原生虚拟宠物原型，用来验证“软萌小狗会回应我讲话”这个核心体验是否成立。

第一版不接真实 AI，不做高精度口型同步，也不做音频实验入口。它只验证最重要的一件事：用户输入一句话或点击示例后，小狗是否足够可爱、反应是否自然、讲话状态是否一眼可懂。

## 2. 目标用户

**P1：内部产品和开发团队。**
他们需要确认第一版 demo 的范围、验收边界和后续实现顺序。

**P2：设计评审者和业务决策者。**
他们需要在不理解技术细节的情况下判断：小狗是否可爱、是否像在讲话、是否值得继续投入真实 AI 对话。

**P3：未来终端用户。**
第一版不验证留存、付费或长期陪伴，只验证核心交互原型是否成立。

## 3. 用户旅程

### UJ-1：评审者用文字让小狗开口

- **进入状态：** App 已加载，小狗处于 `idle`，嘴巴闭合。
- **路径：** 用户输入一句话，点击 `让狗狗说话`；小狗进入准备或思考状态；随后进入讲话状态；讲话结束后短暂反馈并回到待机。
- **价值时刻：** 用户看到小狗张口或轻微开合，并配合耳朵、眼睛、头部、身体或尾巴的小动作，感觉它在回应。
- **边界情况：** 如果用户提交空文本，小狗闭口进入 `error`，提示 `先输入一句话`。

### UJ-2：评审者一键播放示例

- **进入状态：** App 已加载，用户不想输入文本。
- **路径：** 用户点击 `播放示例`；小狗完成准备、讲话、完成、回待机。
- **价值时刻：** 用户无需麦克风权限、上传文件或理解调试台，也能稳定看到小狗讲话效果。

### UJ-3：开发者验证最小边界

- **进入状态：** 开发者运行测试或手动验收。
- **路径：** 检查非空文本、空文本、播放中重复触发、减少动态、横竖屏布局和 TalkBack 语义。
- **价值时刻：** 开发者确认当前 MVP 没有被旧的口型同步、上传、麦克风或调试台范围拖大。

## 4. 术语表

- **数字狗 / 小狗**：平板展示端中的虚拟宠物主体，是用户观察和互动的核心对象。
- **宠物舞台**：承载小狗形象、项圈状态和主要动作表现的主视觉区域。
- **讲话嘴**：当前 MVP 中 `speaking` 状态下的张口或轻微开合视觉表现，不代表精确 viseme。
- **轻量状态摘要**：展示当前状态、输入来源和嘴巴状态的 UI 区域，用于替代旧调试台。
- **文本主入口**：用户输入文本并点击 `让狗狗说话` 的主演示入口。
- **示例入口**：点击 `播放示例` 后触发预设讲话动画的稳定演示入口。
- **宠物状态机**：当前包含 `idle`、`thinking/preparing`、`speaking`、`done`、`error`，可保留 `listening` 作为未来 AI 预留状态。
- **Deferred 能力**：旧方案中移出当前 MVP 的精确口型同步、调试台、上传和麦克风能力。

## 5. 功能需求

### FR-1：首屏宠物舞台

用户启动 Redmi Pad SE 展示端后，可以在首屏看到小狗、文本输入、主 CTA、示例入口和轻量状态摘要。

**可测试结果：**

- 横屏等价视口下，小狗舞台是视觉中心。
- 竖屏等价视口下，文本输入、主 CTA 和示例入口仍可达。
- 核心控件不重叠，按钮和标签不溢出。
- 首屏不是营销页，也不是复杂调试台。

### FR-2：待机闭口

小狗在未讲话、准备、完成、错误恢复后保持闭口。

**可测试结果：**

- 页面加载后嘴巴为 `closed`。
- 非 `speaking` 状态嘴巴为 `closed`。
- 讲话结束后自动回到 `idle` 和 `closed`。

### FR-3：宠物状态机

系统支持最小讲话状态流，并通过小狗动作、项圈状态和状态摘要表达变化。

**可测试结果：**

- 文本或示例触发后，状态按准备/思考、讲话、完成、待机顺序变化。
- 空输入进入 `error`。
- 每个状态有可读文字表达。

### FR-4：自然克制的宠物动作

小狗在讲话前、讲话中和讲话后有少量自然动作，但动作不得干扰嘴巴观察。

**可测试结果：**

- 准备阶段可观察到耳朵竖起、看向用户或歪头，嘴巴仍闭合。
- 讲话中嘴巴开合是最高优先级视觉变化。
- 讲话中头部、耳朵、身体或尾巴动作幅度低，不遮挡嘴巴。
- 讲话结束后可出现一次短暂眨眼、摇尾或开心表情。

### FR-5：文本主入口

用户可以输入文本并触发小狗讲话动画。

**可测试结果：**

- 非空文本点击 `让狗狗说话` 后进入讲话流程。
- 空文本点击不触发讲话，并显示 `先输入一句话`。
- 播放中不会创建第二个冲突讲话流程。

### FR-6：示例入口

用户可以不输入文本，一键触发稳定示例。

**可测试结果：**

- 点击 `播放示例` 后小狗完成完整讲话循环。
- 示例入口不请求麦克风权限。
- 示例流程与文本流程共享状态、嘴巴规则和完成反馈。

### FR-7：轻量状态摘要

界面显示当前状态、输入来源和嘴巴状态。

**可测试结果：**

- 状态摘要可显示 `待机`、`准备中`、`讲话中`、`完成`、`需要处理`。
- 输入来源可显示 `文本` 或 `示例`。
- 嘴巴状态可显示 `闭口` 或 `讲话嘴`。
- 状态颜色必须配合文字、标签或图标表达。

### FR-8：可恢复错误

空文本和播放中重复触发必须可恢复。

**可测试结果：**

- 空文本不触发讲话。
- 小狗进入 `error`，嘴巴为 `closed`。
- 错误文案靠近输入区。
- 用户可继续编辑文本或播放示例。

### FR-9：横竖屏与可访问性

Demo 在 Redmi Pad SE 横屏和竖屏核心流程可用，并支持基础无障碍。

**可测试结果：**

- 横屏和竖屏核心控件无重叠。
- 按钮、文本输入、示例入口触控目标不小于 48dp。
- TalkBack 可读出当前状态、输入来源、嘴巴状态和错误原因。
- 减少动态时保留讲话嘴，降低装饰动作。

### FR-10：未来 AI 状态预留

系统可以保留 `listening` 或等价预留状态，但当前 MVP 不接真实 AI。

**可测试结果：**

- 当前实现不需要真实 AI、ASR 或云端 TTS。
- 未来接入 AI 时，不需要重命名核心状态含义。

## 6. 非目标

当前 MVP 不做：

- 精确口型同步。
- 7 类嘴型产品验收。
- 文本到嘴型时间轴生成作为强制路径。
- TTS 文本高亮、波形、嘴型时间轴、延迟校准。
- 上传音频、麦克风录音、音频分析。
- 真实 AI 对话、云端 TTS、ASR、账号、历史记录、多宠物、多皮肤。

## 7. MVP 范围

### 范围内

- Android 原生单屏 demo。
- 小狗宠物舞台。
- 文本主入口。
- 示例入口。
- 最小宠物状态机。
- `speaking` 开口、非 `speaking` 闭口。
- 俏皮但克制的动作反馈。
- 轻量状态摘要。
- 空文本错误恢复。
- 横竖屏布局、减少动态和 TalkBack 基础语义。

### 范围外

- 完整调试台。
- 上传和麦克风实验入口。
- `LipSyncTimeline` 新能力。
- 高精度 viseme、phoneme 或音频分析。

## 8. 成功指标

- **SM-1：首屏理解。** 评审者打开 App 后，无需说明即可知道可以输入文字或播放示例让小狗讲话。
- **SM-2：讲话感成立。** 点击主 CTA 或示例后，小狗在 `speaking` 状态有明显讲话嘴。
- **SM-3：闭口规则稳定。** 非 `speaking` 状态嘴巴闭合。
- **SM-4：流程完整。** 文本和示例都能完成准备、讲话、完成、回待机。
- **SM-5：错误可恢复。** 空文本不会触发讲话，用户可继续操作。
- **SM-6：范围守住。** 默认 UI 不出现波形、时间轴、文本高亮、延迟校准、上传或麦克风。
- **SM-7：布局可用。** Redmi Pad SE 横屏和竖屏核心控件无重叠、无文字溢出。

## 9. 风险与处理

| 风险 | 处理方式 |
| --- | --- |
| 简化后不像在讲话 | `speaking` 状态保证嘴巴开合，并增加低幅度头部、耳朵或身体动作 |
| 动作过多显得乱 | 讲话嘴优先，其他动作幅度低且不遮挡嘴巴 |
| 旧口型同步范围回流 | PRD、MVP、UI、Epic 和架构文档都标记 Deferred，并增加边界测试 |
| UI 过于工具化 | 默认不展示调试台，只保留轻量状态摘要 |
| 空文本破坏演示 | 进入可恢复错误，保留示例入口 |
| 减少动态后体验消失 | 降低装饰动作，但保留讲话嘴开合 |

## 10. 定稿决策

1. 当前 MVP 的产品目标是“可爱小狗讲话动画”，不是“精确口型同步”。
2. 文本和示例是唯一默认入口。
3. 默认 UI 不显示上传、麦克风、波形、时间轴、文本高亮或延迟校准。
4. 讲话嘴可以是单一张口状态或轻微开合循环。
5. 7 类嘴型和 `LipSyncTimeline` 不保留在当前 production 路径；未来恢复必须重新批准范围。
6. 后续恢复精确同步、调试台或实验音频入口，必须先通过新的 scope change。

## 11. Deferred Backlog

以下旧能力不属于当前 MVP：

- 7 类嘴型产品验收。
- `LipSyncTimeline` 生成、平滑、播放时间驱动和延迟偏移。
- TTS 文本高亮。
- 波形和嘴型时间轴。
- 延迟校准。
- 上传音频。
- 麦克风录音。
- 音频解码、基础音频分析和实验质量标识。
- 完整调试台和同步可信度分析。

这些能力后续可作为新的 Epic 重新评估和拆分。
